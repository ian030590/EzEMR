EzEMR 是在瀏覽器中使用的復健病歷工具，可管理個案基本資料、SOAP 紀錄、症狀評分、評估與訓練結果，並追蹤復健進度。直接以電腦版 Chrome 或 Edge 開啟 [EzEMR.html](EzEMR.html)，不需要安裝應用程式、啟動伺服器或執行建置。

EzEMR 支援繁體中文與英文。`EzEMR.html` 是產生的單檔發佈版；開發原始碼放在 `src/`，第三方元件放在 `vendor/`。

## 🗂 功能

- 管理個案基本資料、診斷、轉介原因與眼部手術史，並從頂部依姓名、病歷號或診斷搜尋。
- 從「設定 → 基本資料欄位…」選擇所有病人都必須填寫的基本資料。
- 每位個案預設開啟「病人總覽」，並有「復健紀錄」、「進度追蹤」與「項目設定」分頁。
- 填寫 SOAP 病歷，記錄基準評估、復健、療程後評估、追蹤評估與缺席。
- 依個案設定初次評估項目；填寫病歷時勾選本次實際做過的評估與復健項目，只有勾選的項目會展開並存入紀錄。每個復健活動各有一個分數。
- 記錄 Eye fatigue、Blurred vision、Dizziness、Headache、Nausea 五項症狀，使用圖表與紀錄類型、日期篩選追蹤變化。
- 比較 COPM 與對應基準紀錄的差異，保存 EyeDot Trainer 訓練紀錄。
- 依個案自訂評估與復健項目模板，不需要修改程式碼。
- 每次病歷儲存為 CSV、PDF 與純文字病歷，另可匯出 Excel、個案總表與完整 JSON 備份。
- 匯入支援格式的評估復能 Excel 資料表與舊版 SOAP JSON 資料夾，保留來源資訊。
- 匯入 OcuTrain 與周邊視野（UFOV）訓練程式產出的分數檔。OcuTrain 每個模組、UFOV 每個子測驗各是一個項目，各有自己的分數與測驗設定。
- 切換深色／淺色外觀，使用鍵盤選單與快捷鍵操作。
- 切換繁體中文／English，保留自行輸入的病歷內容與自訂項目名稱原文。

## ▶ 快速開始

1. 將 `EzEMR.html` 下載到電腦的本機資料夾，再從檔案總管以電腦版 Chrome 或 Edge 開啟。
2. 使用語言選擇器切換「繁體中文／English」。預設為繁體中文，瀏覽器會記住選擇；切換時保留正在填寫的 SOAP 草稿。
3. 第一個畫面會詢問病歷的儲存位置。建立新資料集時，按「使用 HTML 旁的 Data 資料夾」；第一次儲存個案時，選擇 HTML 所在的資料夾並允許編輯，程式會在其中建立 `Data`。已有病歷時，按「開啟既有病歷資料夾」，選擇包含 `clients.csv` 的位置。之後可從「檔案 → 儲存位置…」更改。
4. 按「新增個案」，填寫姓名、病歷號與其他基本資料。想先試用時，可在歡迎畫面按「載入範例個案（示範資料）」。
5. 選取個案，在主區的病人姓名旁按「新增紀錄」，填寫 SOAP 與症狀評分。在「評估項目」與「復健項目」勾選本次做過的項目，展開欄位後填寫結果。
6. 按「儲存」，或使用 `Ctrl+S`／`⌘S`，將本次 CSV、PDF 與 TXT 寫入該個案的資料夾。
7. 再次開啟 HTML 時，若瀏覽器仍允許存取，程式會重新連接先前選取的病歷資料夾；否則第一個畫面會提供重新連接該資料夾或選擇其他資料夾。

瀏覽器需要你選取資料夾並授權，無法自行取得 HTML 的目錄後直接寫入。預設 `Data` 會建在第一次儲存時選取的位置內。

### 病人資料

`EzEMR.html` 與本儲存庫不含任何個案資料；範例個案與所有測試資料皆為虛構。病歷只會寫入你選取的本機資料夾，程式不會透過網路傳送病歷資料。若將預設的 `Data` 資料夾放在本儲存庫的 clone 內，`.gitignore` 會排除它，避免誤將病歷提交。請勿在 issue 或 pull request 中附上真實病歷、匯出檔或備份。

頂部包含個案搜尋、標題、選單、工具與語言選擇器，向下捲動時仍固定可用；不保留側欄或完整名冊。輸入姓名、病歷號或診斷後，最多顯示八筆符合結果；空白搜尋不列個案。使用上下方向鍵與 Enter 選取，Escape 關閉結果。切換個案會保護未儲存草稿，舊選取的延遲回應也不會取代目前病歷。互動文字使用 13px、框內上下 padding 各為 2px，保留至少 44px 操作範圍；頂部控制項外側各留 8px，桌面高度為 61px，相鄰按鈕的尺寸與間距一致。儲存位置可從「檔案 → 儲存位置…」查看，不占用頂部空間；窄螢幕會換行。

個案摘要優先顯示姓名、病歷號與診斷，接著是紀錄總數、最近紀錄日期，以及最近一筆紀錄中的下次復健日期；基本資料與病歷來源收合在下方。選取個案預設開啟「病人總覽」，先列症狀分數，再依序呈現所選紀錄的症狀與功能、推理與依據、介入與計畫。預設選最近出席紀錄，選單排除缺席；選擇較舊紀錄時有明確標示。最近一筆若為缺席，會顯示日期提示，只有缺席紀錄的個案也會提示。各次紀錄的結果與推理分別呈現。

「復健紀錄」分頁顯示症狀圖表與由新到舊排列的紀錄歷程；寬螢幕時圖表在歷程旁，窄螢幕時在歷程上方。每筆紀錄以有標籤的三欄對齊復健前、復健後與差異；各測驗分數、評估數量、恢復時間、耐受度與復健項目分組排列，缺席紀錄則分列原因、通知與改約。編輯器中的症狀與 COPM 摘要也採用有標籤的分數組。依紀錄類型與日期篩選只改變列出的紀錄，不影響個案摘要。「進度追蹤」顯示症狀變化、評估結果、COPM 比較與訓練紀錄；「項目設定」管理該個案的評估與復健模板。

首次開啟時跟隨系統外觀，從「設定」手動切換後，設定會記在目前的瀏覽器。兩種外觀沿用相同的資訊層級；Noto Sans TC 使用電腦已安裝的字體，無法使用時由系統字體備援。Metro 圖示字型已內嵌。

### 全域必填基本資料

開啟「設定 → 基本資料欄位…」，可設定目前病歷資料夾內所有病人，或瀏覽器儲存中的所有病人，必須填寫的欄位。共有十四項：姓名、病歷號、身分證字號、生日、性別、抽菸、飲酒、嚼檳榔、職業、宗教、慢性病、電話、地址與過敏史；預設勾選姓名與病歷號。

勾選的欄位在儲存個案與病歷時必填；未勾選的欄位不顯示，已存內容仍保留。新增要求後，舊病歷仍可讀取，缺少必填資料的病人須先補齊才能寫入紀錄；正在編輯的 SOAP 草稿會保留。未具名個案使用顯示用標籤，不把翻譯後的占位文字寫入姓名。資料夾設定儲存在 `settings.json`，瀏覽器另存自己的設定，完整 JSON 備份也包含設定。CSV 欄位結構不變，新增的基本資料沿用既有額外欄位內容保存。

## 臨床推理與病歷結構

### 病人總覽與臨床連結

總覽依提供的《視覺復健服務架構》呈現：**視覺功能／功能性視覺評估 → 個人、環境、作業（PEO）推理 → 面對面／遠距復健介入 → 質性與量化報告**。選取病人時預設開啟「病人總覽」，可選擇要看的出席紀錄，缺席紀錄不列入選單。在病歷 A 區，為每個主要症狀或功能困難新增一筆臨床連結，選擇評估分類、填寫臨床推理、勾選 PEO 面向，以該次評估結果作為依據，再勾選相關的復能、調適或代償策略。依據與介入備註保留治療人員原文；總覽並列呈現每筆症狀、推理與依據、介入處置的關係。

依據引用選定紀錄中的結果及當時儲存的評估定義，未記錄的評估會顯示缺少依據的提示。切換服務型態保留已選的策略。沒有臨床連結的舊紀錄，分別列出原有症狀、推理與介入，不自行建立關聯；程式不會自動做臨床推理或選擇處置。簡報沒有獨立的症狀分類清單，程式連結分類採「視覺功能」與「功能表現」，後者涵蓋功能性視覺及一般復健。簡報面對面復能的「視覺知覺」對應英文誤植為 Visual field training，本程式採中文原意，英文顯示 Visual perception。

連結儲存在病歷的 `clinicalLinks` 陣列中，評估與介入使用固定識別碼，沿用原 CSV 格式並保留於 JSON 備份。TXT、PDF 與 Excel SOAP 表單包含連結文字；Excel 總表另有 **Clinical links** 工作表，每項症狀一列。缺席紀錄中保留的草稿連結不列入臨床報告。切換介面語言不翻譯評估結果或臨床文字。

編輯器保留 SOAP，依臨床評估到介入的流程排列：**S 主觀描述**、**O 評估**（觀察、症狀 NRS 與評估項目）、**A PEO 臨床推理**、**P 介入與計畫**。個人、環境、作業的評估發現，用來形成臨床判斷與介入規劃。P 依序包含**復能**（既有復健項目、活動分數、測驗紀錄、EyeDot 與其他治療／居家計畫）、**調適**、**代償**、耐受度、後續計畫與下次復健日期。

在基本資料選擇**面對面**或**遠距復健**。新紀錄預設面對面；沒有服務型態的舊紀錄顯示**未指定**，直到自行選擇。調適與代償各有對應服務型態的勾選策略與備註。切換服務型態會保留另一型態已勾選的策略，並標示該型態名稱，其他草稿內容也會保留。P 的復能區記錄訓練活動與結果；A 的逐項症狀連結則記錄服務架構的介入分類，以及各症狀的實際處置或計畫。

紀錄的 `mode` 儲存 `inperson`、`telerehab` 或未指定值；`peo` 包含選填文字 `person`、`environment`、`occupation`。`interventions.adaptation` 與 `interventions.compensation` 各含 `picks`（固定 ASCII 策略識別碼）及選填 `notes`。讀取舊紀錄不會補上原本沒有的新欄位；在編輯器儲存時可加入，未選擇服務型態則維持未指定。未知但格式正確的策略識別碼直接顯示原值。切換語言只改標籤，不改臨床文字或儲存值。

本機資料夾沿用原 CSV 結構，不新增 CSV 欄位，巢狀資料可經 CSV 重新載入與完整 JSON 備份保存。TXT、PDF 與 SOAP 表單 Excel 依相同流程排列。Excel 的 **SOAP notes** 工作表在原有欄位後新增服務型態、PEO、調適與代償欄位；**Interventions** 工作表每個勾選策略各列一筆，包含個案、日期、次數、服務型態、介入方式、策略識別碼與目前語言的標籤，供量化報告使用。

### 症狀評分與來源

眼睛疲勞、視線模糊、頭暈、頭痛、噁心與各項 0 至 10 分的題目，在最初的應用程式版本（`af3ec91`）就已存在。原始註解提到「症狀評分說明」，但儲存庫沒有附上該文件，也沒有這個五項組合的量表或文獻引用；提供的服務架構簡報亦未指定這五項。現行加總沒有加權，只加上已填的項目，略過空白，全部空白才不顯示總分。目前專案紀錄不足以確認此加總是經驗證的量表。

總覽比較所選紀錄內第一與最後一個有評分的時間點，排除恢復後評分，以正負數值呈現差異：「本次變化」的降低為綠色、升高為紅色、相同為中性色。缺少評分時保留空白標記，不計算差異。顏色只表示變化方向，不判定嚴重程度或產生臨床結論。紀錄卡片仍以「與首次差異」呈現同次第一筆與復健後評分的差異；臨床稜鏡度數欄位保留其單位符號。

## 自訂評估與復健項目

選取個案後，開啟「項目設定」：

1. 按「新增評估項目」或「新增復健項目」，選擇內建模板或空白模板。
2. 填寫項目名稱。評估可設定分類、領域、填寫說明與評估時機；COPM 固定屬於功能表現。復健可設定活動清單，每行一項。
3. 新增結果欄位，選擇文字、數值、長文字或選單。數值可設定單位、最小值、最大值與間隔；選單選項每行一項。
4. 按「儲存項目」，之後即可在 SOAP 表單勾選並填寫。也可直接從正在填寫的 SOAP 表單新增項目，原有草稿會保留。

### 評估分類

O 先填觀察與客觀描述，再依序顯示**視覺功能**（症狀 NRS 在前）與**功能表現**。後者涵蓋功能性視覺及步行、上肢操作、輪椅移位等一般復健；分類識別碼仍是 `visual` 與 `functional`，既有病歷與已儲存領域不改寫。個案沒有啟用視覺評估且未填視覺症狀時，視覺症狀區會收合為選填。兩組各有評估勾選及應評估／其他項目清單。TXT／PDF、SOAP 表單 Excel 與進度追蹤沿用兩組；Excel 的 **Assessments** 與 **Data collection plan** 工作表在原有欄位後新增 **Category**，顯示目前語言的分類名稱。

標準模板在視覺功能新增病歷資料、視光紀錄、職能治療評估紀錄、視力、屈光、近距離視力、視野、對比敏感度、色覺及立體視；功能表現新增自填問卷、職能治療評估、日常作業表現及參與需求，並保留既有 COPM 與工作相關功能性視覺作業。三項紀錄檢閱與自填問卷採基準、療程後與追蹤時機，其餘新增項目採每次評估。使用標準模板或由 Excel 匯入建立的新個案，初次評估項目預設全部不勾選，請在「項目設定」勾選。既有個案與未儲存選擇的項目維持原本納入的規則；從另一個案建立的個案保留來源個案的選擇。

既有個案保留原本儲存的模板。可從「項目設定 → 新增評估項目 → 從模板開始」選擇新增的內建項目並儲存；分類會隨模板帶入，也可在項目對話框修改。分類只儲存 `visual` 或 `functional`。未存分類的舊項目預設為視覺功能，COPM、工作相關功能性視覺作業及新增的功能性項目則為功能表現。切換語言不改寫項目定義、結果、本機資料夾 CSV 檔名或結構。

### 短期成效指標

依提供的指標整理新增 14 個模板：視覺搜尋、空間忽略／注意、閱讀、NPC、PFV、視覺動作協調、注視／掃視、TUG、10MWT、BBT、9HPT、COP、症狀／恢復耐受性、固定負荷症狀誘發。使用標準模板的新個案已包含這些項目，評估時機為「每次復健」；既有個案可從「新增評估項目 → 從模板開始」選取，不改寫早期病歷或長期評估。新個案的初次評估項目仍預設不勾選。

每個模板都有「訓練前 1」、「訓練前 2（選用）」、「訓練後立即」、「恢復期（選用）」及「24–72 小時追蹤（選用）」。請填實際測量時間與等值題型，訓練後註明距訓練結束幾分鐘，追蹤註明日期與時間。訓練前 1 與立即後直接展開，其餘時點可收合，有結果時自動展開。空白表示未測，0 會保留；NPC 平均請由重複測量結果填入。「測驗設定」可記錄工具、流程、計分規則、條件、擇一主要指標、介入內容與對照條件。結果及時點標籤會保留於進度追蹤、本機資料夾 CSV、TXT、PDF 與 Excel 匯出。

主要指標應選擇與訓練目標對應的客觀功能結果，搭配次要表現指標，另記症狀與耐受性。搜尋搭配時間、正確率及漏答；忽略加上左右漏答與線段平分；閱讀搭配速度、錯誤與理解；雙眼視覺搭配 NPC／PFV；視覺動作搭配時間／命中率及反應時間／誤差。功能改善時症狀仍可能暫增。固定負荷誘發量＝負荷後分數－該次負荷前分數，應使用相同負荷並考量基線、天花板效應、自然恢復及重測。程式記錄分數，不自動判定療效或計算臨床門檻。

「項目設定」及評估編輯器可展開「短期成效指標與施測流程」，查看建議組合與解讀限制。立即測量為訓練結束至約 30 分鐘，恢復可於 15–30 分鐘及 24–72 小時追蹤。固定施測條件、使用等值刺激；推論因果時宜加入合理對照。施測方便不表示對單次變化敏感。VOMS 為篩檢；Barthel、FIM、NEI VFQ-25、CBS、MVPT 不宜優先作單次立即主要指標，視力、視野及對比敏感度則依訓練目標決定。正式研究須依族群查核信效度、MDC、MCID（如有）與授權，不假設有單次 MCID。此功能實作提供的研究設計整理，不是臨床指引或系統性回顧。

短期進度逐次顯示病歷，將測量時點改成列，只顯示有施測的指標欄，測試條件與備註收合在下方。數值先於測量時間，手機直接顯示第一項結果，其他欄位有橫向捲動提示。未填症狀不產生空白症狀表，0 仍是有效測量值。總覽摘要短期結果，不重複鋪陳完整測試設定；未填原有視覺症狀、但已記錄疼痛或其他短期耐受性分數時，顯示已測分數而非缺漏提示。完整條件與時間保留於病歷及匯出。未改動的內建模板保留雙語標籤，自訂名稱與臨床文字維持原文。

依 `tests/VERIFICATION.md` 安裝測試依賴後，執行 `node tests/clinical-samples.cjs` 可建立六位虛構個案與 19 筆紀錄：中風、腦傷、脊髓損傷輪椅移位、低視能閱讀、雙眼視覺，以及術後步行復健。忽略的 `.tmp/verification/clinical-samples/after/` 中有可匯入的 `synthetic-records.json`、包含 CSV／PDF／TXT 的 `records/` 資料夾、畫面截圖與版面量測。假病歷不會嵌入應用程式。

### 視野填寫

內建「視野」評估參考 NTUHLowvision 的十字填寫方式。面對病人時，畫面左側為右眼 OD、右側為左眼 OS，鼻側朝中間、顳側朝外；雙眼 OU 放在下方，病人的右側顯示在畫面左側。每個十字有四個方向，共十二個自由文字欄位，可填角度或質性描述；空白表示未記錄，`0` 會保留為結果。窄螢幕會將三個十字依序堆疊。

測驗／方法、舊有 OD 與 OS 記載、摘要及自訂欄位仍可使用。從來源資料表匯入的視野採相同排列，原始欄位識別碼與結果保持不變。切換語言保留已輸入的文字；程式不會判讀視野或產生臨床結論。

### 初次評估項目

「項目設定」最上方的「初次評估項目」以勾選方塊列出個案所有啟用中的評估項目。使用標準模板或由 Excel 匯入建立的新個案預設全部不勾選。請勾選初次評估（基準評估）要施測的項目，每次變更都會立即儲存。既有個案保留已儲存的選擇，未儲存選擇的項目仍列入。從另一個案建立的個案保留來源個案的初次評估選擇。

病歷中的評估項目改用勾選方塊，做法參考 NTUHLowvision 的門診評估表單：

- 「基準評估」先列出初次評估項目，其餘列在「其他項目」。
- 「療程後評估」與「追蹤評估」將初次評估項目中依評估時機應再評估的項目列為「本次應評估」，其餘列在「其他項目」。
- 一般復健紀錄將「每次復健」項目列於「本次應評估」，其餘可用項目列在旁邊。COPM 只在基準與療程後評估顯示。

勾選項目後展開結果欄位；取消勾選會收合，離開這筆紀錄前已輸入的內容仍保留。只有勾選的項目會存入紀錄，沒施測的項目不會出現在病歷、PDF、Excel 或進度追蹤。舊紀錄中未勾選但已存有的結果會保留。

### 復健項目與活動分數

復健項目採相同方式：勾選本次進行的項目後展開。在項目內勾選做過的活動，每個勾選的活動各有一個分數欄，例如 `85%`、`12 次` 或 `40 秒`。其後為共用的程式／設備、時間、級別／設定、個案自評難度（0 至 10）與觀察，再接自訂結果欄位。沒有活動清單的項目改為單一「表現」欄。舊紀錄使用過的共用表現欄會以「整體表現」保留。

活動分數會寫入病歷、PDF 與 TXT（例如「選擇性注意力：92%」），在 Excel 的 Training results 工作表各占一列，在「進度追蹤」中每個活動各占一欄；✓ 表示有做但未填分數。自評難度與整體耐受度改用 0 至 10 的數字欄，空白代表未評分，超出範圍時無法儲存。COPM 保留專用表格、評估時機及基準比較。

### 電腦化視覺測驗（OcuTrain 與 UFOV）

內建的電腦化測驗依照 OcuTrain 的模組與周邊視野訓練程式的子測驗設定。每個模組或子測驗是獨立的項目，平滑追視與凝視不會寫在同一項：

| 項目 | 主要分數 | 其他結果 | 測驗設定 |
| --- | --- | --- | --- |
| 平滑追視（OcuTrain PURSUIT） | 注視正確率（%） | 完成目標數、命中時間、有效注視時間、測驗時間、各方向複視出現位置 | 測驗模式、刺激類型與大小、移動速度、目標範圍、方向、命中距離閾值、觀看距離、眼動儀 |
| 凝視（OcuTrain FIXATION） | 注視正確率（%） | 同平滑追視 | 同平滑追視，另加邊緣停留時間 |
| 跳視（OcuTrain SACCADE） | 注視正確率（%） | 平均首次凝視時間（TFF）、TFF 目標數及上述結果 | 測驗模式、刺激、目標停留時間、範圍、方向、閾值、距離、眼動儀 |
| 前庭眼反射（OcuTrain VOR） | 注視正確率（%） | 命中時間、有效注視時間、測驗時間、複視 | VOR 倍率、VOR 方向、刺激大小、閾值、距離、眼動儀 |
| UFOV 子測驗 1 至 3（處理速度、分散注意力、選擇性注意力） | 80% 正確門檻（ms） | 整體正確率、平均反應時間、正式題數與答對題數、最快正確呈現時間；子測驗 2、3 另有中央與周邊正確率及各方向正確率 | 停止條件、對比度、車輛大小、觀看距離、螢幕更新率；子測驗 2、3 另有周邊偏心視角與啟用方向 |

主要分數排在第一欄。測驗設定收合在結果下方的「測驗設定」區，標題會顯示已填幾項。欄位代碼沿用兩個程式匯出檔的鍵名，匯入的數值會填入相同的欄位。病歷、PDF 與進度追蹤以一行摘要顯示設定。

復健紀錄也可以記錄測驗。勾選「電腦眼球運動訓練」或「周邊覺察」後，「測驗紀錄」每次測驗列一張卡片。選擇模組或子測驗後按「新增測驗紀錄」即可手動填寫。每張卡片有自己的結果與設定，同一次復健做的追視與凝視會分開記錄。測驗紀錄會寫入病歷與 PDF，在 Excel 的 Training results 工作表各占一列，並在進度追蹤中以獨立標題顯示。

既有個案保留原本存好的項目模板。舊的項目，例如合併的凝視、追視項目，仍可使用，已存的結果不變。可從「項目設定」加入新項目，或由匯入測驗分數時自動加入。

每個項目可編輯、複製、停用或再次啟用。已儲存的病歷保留當時的項目名稱與欄位定義，後續模板改名、移除欄位或停用，不會改寫歷史結果。舊版尚未保存定義的病歷，會在第一次修改設定時，由個案資料保留原模板。

新增個案時，「評估與復健項目模板」可複用其他個案的項目定義，只複製設定，不複製病歷或評分；兩位個案後續的設定各自保存。

## 💾 儲存結構與檔案格式

HTML 沒有寫死病歷資料夾的絕對路徑，選擇儲存位置也不會修改 HTML 檔案。病歷會存在 HTML 旁或你選擇的其他本機資料夾。

使用預設 `Data` 位置時的資料夾範例：

```text
EzEMR/
  EzEMR.html
  Data/
    clients.csv
    MRN-001/
      2026-10-30_S01_基準評估.csv
      2026-10-30_S01_基準評估.pdf
      2026-10-30_S01_基準評估.txt
      2026-10-31_S02_復健.csv
      2026-10-31_S02_復健.pdf
      2026-10-31_S02_復健.txt
```

個案資料夾使用病歷號命名，未填病歷號時使用姓名。病歷檔名由日期、次數與紀錄類型名稱組成；切換介面語言不會更改既有檔名。

| 檔案 | 內容與行為 |
| --- | --- |
| `clients.csv` | 每位個案一列，包含識別碼、資料夾名稱、姓名、病歷號、出生與發病日期、診斷、轉介原因、手術史、評估與復健模板、建立日期及額外資料。手術史與模板等巢狀資料以 JSON 格式放在單一 CSV 儲存格內。 |
| 每次病歷的 `.csv` | 每個欄位一列，包含 `schema_version`、`section`、`field`、`type`、`value` 五欄，保存數值、空值、勾選狀態、症狀、評估、COPM 與訓練資料，可重新匯入。例如 `section` 為 `session`、`field` 為 `/subjective` 的資料是主觀描述。 |
| 每次病歷的 `.pdf` | A4 圖像版文件，自動換行與分頁，可閱讀及列印。文字無法直接選取或搜尋，需要搜尋或分析資料時請使用 CSV。 |
| 每次病歷的 `.txt` | 同一份病歷的純文字版，使用儲存時的介面語言。每次儲存都會重寫，程式不會讀回；重新匯入請使用 CSV。 |

CSV 使用 UTF-8 BOM，支援中文與 Excel 開啟。新增、編輯、項目設定或刪除個案時會更新 `clients.csv`，不需要另外的 JSON 資料庫。

每次新增病歷產生一組 CSV、PDF 與 TXT；編輯同一筆紀錄會更新原有檔案。檔名在首次儲存時決定，之後修改日期或次數仍保留原檔名，實際資料以檔案內容為準。不同紀錄的檔名相同時，會自動加上編號避免覆寫。

### 瀏覽器如何記住資料夾

主要病歷資料夾與選用的副本資料夾，會以檔案系統控制代碼（handle）記在瀏覽器的 IndexedDB。這些資料夾參照不會寫入 `EzEMR.html`，也不包含在 JSON 備份中。啟動時，若記住的主要資料夾仍有權限，便會自動連接；否則第一個畫面會提供重新連接。可從「檔案 → 開啟病歷資料夾」切換資料夾。

`Data` 只是固定的預設子資料夾名稱，並非固定路徑。程式會在首次儲存時選取的上層資料夾內建立或開啟它。若要放在 HTML 旁，請選擇 `EzEMR.html` 所在的資料夾。重新開啟既有病歷時，請直接選取 `Data`，或其他包含 `clients.csv` 的病歷資料夾。

換瀏覽器、瀏覽器使用者設定檔或電腦後，需要重新選取資料夾並授權。清除瀏覽器資料會移除記住的資料夾存取資訊與存在瀏覽器中的紀錄，但不會刪除已儲存在本機病歷資料夾的檔案。

### 更換儲存位置

開啟「檔案 → 儲存位置」。可以直接選擇 HTML 所在的資料夾，讓 `clients.csv` 與 HTML 放在同一層，也可以使用 `Data` 或其他本機資料夾。已有病歷時，選擇包含 `clients.csv` 的資料夾；開始新的資料集時，選擇空資料夾。切換後會讀取新位置，原位置的檔案仍保留，不會自動搬移或複製病歷。

### 重新讀取本機資料

本程式直接讀寫你選取的本機資料夾。在程式外修改檔案後，可選「檔案 → 重新讀取資料夾」載入變更。

### 更新程式或搬移病歷

更新程式前，先儲存草稿並保留完整病歷資料夾；使用瀏覽器儲存時，請匯出完整 JSON 備份。更換 `EzEMR.html` 後，再視需要重新連接既有資料夾或還原備份。移動 HTML 不會搬移本機病歷資料夾。

需要換資料夾或電腦時，先儲存正在編輯的草稿，再選擇其中一種方式：

- 複製完整病歷資料夾，包含 `clients.csv` 與所有個案子資料夾；換電腦時也要複製 `EzEMR.html`。開啟 HTML 後，從「檔案 → 開啟病歷資料夾」選擇複製後包含 `clients.csv` 的資料夾。此方式保留既有檔案與檔名。
- 從「備份全部資料（JSON）」匯出備份，將備份與需要的 `EzEMR.html` 複製到新位置。開啟 HTML，選取空的目的病歷資料夾，再以「匯入」還原 JSON。還原會將個案資料寫入選定位置，並建立各次病歷的 CSV、PDF 與 TXT。

如果使用第二個副本資料夾，請在目的地的瀏覽器重新設定。

## 匯入、匯出與備份

- 從工具列「匯入」或「檔案 → 匯入 CSV／評估復能 Excel／備份／測驗分數」，可一次選擇多份本程式產生的 CSV、匯入個案總表、還原單一完整 JSON 備份、讀取支援格式的 `.xlsb`／`.xlsx` 來源資料表，或匯入測驗分數檔。Excel、CSV、JSON 與測驗分數檔請分開匯入。
- 從「匯出 → 匯出個案總表 CSV」下載 `clients.csv`；「匯出個案 Excel／匯出全部個案 Excel」產生活頁簿；「備份全部資料（JSON）」保存完整資料備份。
- 自訂評估、復健與結果欄位會出現在進度追蹤、CSV、PDF、Excel 與完整備份。即使篩選到療程後紀錄，COPM 仍會與完整歷程中對應的基準紀錄比較。
- 資料夾模式可從「檔案 → 設定副本資料夾」選擇第二個本機資料夾。連接時複製既有資料，之後的寫入、重新命名與刪除也會套用至副本；需要保留不受後續刪除影響的版本時，另行保存 JSON 備份。

### 測驗分數檔

先選取個案，再按「匯入」並選擇一或多個分數檔。程式依檔案內容辨識格式，不看檔名：

- OcuTrain 的 JSON 匯出檔（包含一個檔案內有多次測驗的情況），以及開頭為 `# Key: Value` 的 OcuTrain CSV 匯出檔。支援追視、凝視、跳視與 VOR。
- 周邊視野（UFOV）訓練程式的統計成績 CSV，欄位為 `參數項目`、`參數代碼`、`設定數值`、`單位`、`詳細說明`。

預覽畫面每次測驗列一張卡片，顯示日期時間、項目、測驗模式、主要分數、檔名，以及「匯入為」選單：「評估」、「復健訓練」或「不匯入」。預設規則：

- OcuTrain 的評估（Evaluation）模式匯入為評估；可預期（Predictable）與隨機（Random）模式匯入為復健訓練。
- UFOV 測驗在同一天已有評估紀錄時匯入為評估，否則匯入為復健訓練。
- 未完成的測驗、UFOV 的練習或說明模式，以及已匯入過的測驗，預設為「不匯入」。匯入前可逐筆修改。

匯入為評估時，會填入當天紀錄中該項目的欄位。匯入為復健訓練時，會在對應的復健項目下新增一筆測驗紀錄，主要分數成為該活動的分數。當天沒有紀錄時，匯入會新增評估或復健紀錄。不會覆蓋已有的結果：數值與已存結果不同的測驗會略過並列在報告中。同一次測驗同時匯出 JSON 與 CSV 時只列出一筆。

檔案中的受試者代號若與其他個案的病歷號相同，匯入會停止。UFOV 原始分數 CSV 只有逐題資料，UFOV 的 JSON 匯出檔沒有記錄測驗模式，兩者都只列為說明、不匯入，請改匯入同一次的統計成績 CSV。與測驗一起存的複視問卷會填入該次的複視欄位；只有問卷的檔案不會匯入。每筆匯入的測驗都會在紀錄的來源資訊中保留檔名、受試者代號、測驗日期時間與匯入鍵值。

### 來源資料表與舊版 SOAP 資料夾

Excel 匯入需要包含「評估及復能收案名單」、「評估紀錄」與「復能紀錄」三張工作表，並沿用來源資料表的欄位結構，不支援任意格式的 Excel。匯入後保留工作表名稱、列號與原始欄位值；個案與病歷畫面會顯示可用的來源資訊及醫療史。

從「檔案 → 匯入舊版 SOAP 資料夾」選擇包含個案子資料夾的上層目錄；每組 JSON 病歷須與該個案的 `client.json` 放在同一資料夾。匯入會略過 `_archive`，同一筆病歷識別碼保留 `updated` 較新的版本，合併符合條件的個案與紀錄，並回報資料衝突。同名但病歷號不同的個案維持分開；缺少病歷號時，姓名只能對應一位個案且出生日期不得衝突，第一個已知病歷號會補入舊資料的空白號碼。同一內部個案識別碼若帶有不同病歷號，會停止匯入。JSON 備份若包含重複個案識別碼，或同一個案內重複病歷識別碼，會在任何寫入前拒絕。整合來源資料前，請先備份目的位置。

### 舊版資料相容性

舊版 `client.json` 與 JSON 病歷仍可讀取。沒有總表時，儲存個案會建立 `clients.csv`；已有總表時以總表為準，格式錯誤會停止讀取，避免覆寫。舊版 JSON 格式錯誤或無法讀取時，會顯示檔名並停止載入；非必要 JSON 檔案不存在時仍正常使用備援流程。編輯個案病歷號會保留既有資料夾與其中檔案。

編輯舊病歷後會產生 CSV、PDF 與 TXT，原有 JSON 保留；同一筆紀錄同時存在 CSV、JSON 時，以 CSV 為準。

## 離線使用與瀏覽器儲存

產生的 HTML 已內嵌 Metro UI 5.1.20 及其 CSS、字型與圖示、SheetJS Community Edition 0.20.3 Excel 讀取元件，以及 xlsx-js-style 1.2.0 含樣式的匯出元件。建置前會核對本機第三方檔案、授權與來源雜湊；使用時不需要 CDN 或安裝應用程式套件，病歷編輯與支援格式的匯入、匯出皆可離線操作。

內容安全政策與最先執行的隱私防護會阻擋網路請求、遠端腳本、內嵌網頁、Worker 與對外表單送出；下載使用本機 Blob URL。EyeDot 模式說明改為本機對話框，可複製說明網址，程式不會開啟外部網站。內嵌元件無法使用時會顯示錯誤，不會改從遠端下載。

瀏覽器不支援資料夾存取時，改用瀏覽器儲存。每次儲存病歷會下載 ZIP，內含以病歷號命名的資料夾與該次 CSV、PDF；未填病歷號時用姓名，兩者皆空白時用固定個案識別碼。請自行解壓縮並合併到病歷資料夾，此模式不會直接更新磁碟上的固定資料夾。

瀏覽器暫存不能取代下載檔或備份。清除瀏覽器資料會移除存在其中的紀錄。

使用產生的主程式不需要安裝套件。開發建置只需要 Node.js，不需要安裝套件或存取網路；修改 `src/` 並將第三方檔案保留在 `vendor/`，不可直接修改產生的 `EzEMR.html`。可直接開啟 `src/index.html` 進行本機資料夾開發，或建置單檔：

```sh
node scripts/build.cjs
node scripts/build.cjs --check
node scripts/build.cjs --output .tmp/preview/EzEMR.html
```

第一個指令更新根目錄的 `EzEMR.html`；`--check` 只檢查它是否符合目前原始碼，不寫入檔案；`--output` 將獨立預覽建在 `.tmp/`。測試會從目前原始碼建置獨立產物，不要求先更新發佈檔。測試驗證另需 Acorn、Playwright／Chromium，以及 Python 的 `pypdf`、`PyMuPDF`；環境設定見 [tests/VERIFICATION.md](tests/VERIFICATION.md)。

安裝測試依賴後，每份 checkout 執行一次，啟用 Git hook：

```sh
git config --local core.hooksPath .githooks
```

之後每次 `git push` 都會先建置 `EzEMR.html`，再執行 `node tests/run-ci.cjs`。GitHub Actions 採相同的建置與完整驗證流程，並上傳產生的單檔 HTML；原始碼為依據，不要求提交中的產生檔在建置前已同步。任何一項失敗都會停止後續步驟並阻止本機推送。`tests/` 直接目錄下新增的 `.cjs`、`.py` 會自動納入。完整 runner 建置一份 `.tmp/ci/EzEMR.html`，透過 `EZEMR_TEST_HTML` 供整套測試使用；單獨執行的測試由 `tests/lib/app.cjs` 建置各程序自己的副本。Excel 測試元件由已驗證的本機 bundle 擷取，不再下載。

每個介面功能都必須具備繁體中文與英文。翻譯檢查會攔截漏翻文字、新增的單一語言標籤、缺少另一種語言的內建項目，以及英文 README 的中文字。新增功能的畫面與狀態也必須納入雙語瀏覽器測試，規則見 [AGENTS.md](AGENTS.md)。

`.tmp/` 已由 Git 忽略，用來存放建置的測試主程式、預覽、結果、畫面與合成匯出檔，使用發佈版不需要這些檔案。

若建置的 HTML 內嵌個案資料，測試會失敗。測試在獨立瀏覽器環境建立合成個案；`imports.cjs` 另直接從磁碟開啟當次建置的單檔 HTML，再使用獨立資料夾測試合成 Excel 與舊版 SOAP 匯入。雙語檢查包含匯入報告、錯誤、來源標籤、日期、重複紀錄與封存排除。原生作業系統資料夾對話框與臨床適用性不在自動化驗證範圍內。

翻譯檢查會排除不可執行的 JSON 資料，並以固定 SHA-256 雜湊驗證內嵌 Metro 與 Excel 元件。應用程式腳本、匯入訊息、無障礙名稱及內建評估項目的雙語標籤仍須通過翻譯檢查。來源資料表的工作表名稱與欄位名稱屬於資料識別值，兩種語言下都保持不變。反例測試確認漏翻介面或修改第三方元件仍會失敗。
