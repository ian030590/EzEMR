EzEMR 是在瀏覽器中使用的復健病歷工具，可管理個案基本資料、SOAP 紀錄、症狀評分、評估與訓練結果，並追蹤復健進度。直接以電腦版 Chrome 或 Edge 開啟 [EzEMR.html](EzEMR.html)，不需要安裝應用程式、啟動伺服器或執行建置。

EzEMR 支援繁體中文與英文，主程式檔名為 `EzEMR.html`。

## 🗂 功能

- 管理個案基本資料、診斷、轉介原因與眼部手術史，並在個案名單依姓名、病歷號或診斷篩選。
- 每位個案分為「復健紀錄」、「進度追蹤」與「項目設定」三個分頁。
- 填寫 SOAP 病歷，記錄基準評估、復健、療程後評估、追蹤評估與缺席。
- 依個案設定初次評估項目；填寫病歷時勾選本次實際做過的評估與復健項目，只有勾選的項目會展開並存入紀錄。每個復健活動各有一個分數。
- 記錄 Eye fatigue、Blurred vision、Dizziness、Headache、Nausea 五項症狀，使用圖表與紀錄類型、日期篩選追蹤變化。
- 比較 COPM 與對應基準紀錄的差異，保存 EyeDot Trainer 訓練紀錄。
- 依個案自訂評估與復健項目模板，不需要修改程式碼。
- 每次病歷儲存為 CSV、PDF 與純文字病歷，另可匯出 Excel、個案總表與完整 JSON 備份。
- 匯入支援格式的評估復能 Excel 資料表與舊版 SOAP JSON 資料夾，保留來源資訊。
- 匯入 OcuTrain 與周邊視野（UFOV）訓練程式產出的分數檔。OcuTrain 每個模組、UFOV 每個子測驗各是一個項目，各有自己的分數與測驗設定。
- 切換深色／淺色外觀，使用鍵盤選單與快捷鍵操作。
- 切換繁體中文／English，保留自行輸入的病歷內容與自訂項目名稱原文。

## ▶ 快速開始

1. 將 `EzEMR.html` 下載到電腦的本機資料夾，再從檔案總管以電腦版 Chrome 或 Edge 開啟。
2. 使用語言選擇器切換「繁體中文／English」。預設為繁體中文，瀏覽器會記住選擇；切換時保留正在填寫的 SOAP 草稿。
3. 第一個畫面會詢問病歷的儲存位置。建立新資料集時，按「使用 HTML 旁的 Data 資料夾」；第一次儲存個案時，選擇 HTML 所在的資料夾並允許編輯，程式會在其中建立 `Data`。已有病歷時，按「開啟既有病歷資料夾」，選擇包含 `clients.csv` 的位置。之後可從「檔案 → 儲存位置…」更改。
4. 按「新增個案」，填寫姓名、病歷號與其他基本資料。想先試用時，可在歡迎畫面按「載入範例個案（示範資料）」。
5. 選取個案，按工具列「新增紀錄」，填寫 SOAP 與症狀評分。在「評估項目」與「復健項目」勾選本次做過的項目，展開欄位後填寫結果。
6. 按「儲存」，或使用 `Ctrl+S`／`⌘S`，將本次 CSV、PDF 與 TXT 寫入該個案的資料夾。
7. 再次開啟 HTML 時，若瀏覽器仍允許存取，程式會重新連接先前選取的病歷資料夾；否則第一個畫面會提供重新連接該資料夾或選擇其他資料夾。

瀏覽器需要你選取資料夾並授權，無法自行取得 HTML 的目錄後直接寫入。預設 `Data` 會建在第一次儲存時選取的位置內。

### 病人資料

`EzEMR.html` 與本儲存庫不含任何個案資料；範例個案與所有測試資料皆為虛構。病歷只會寫入你選取的本機資料夾，程式不會透過網路傳送病歷資料。若將預設的 `Data` 資料夾放在本儲存庫的 clone 內，`.gitignore` 會排除它，避免誤將病歷提交。請勿在 issue 或 pull request 中附上真實病歷、匯出檔或備份。

寬螢幕向下捲動時工具列仍固定可用；窄螢幕的工具列則隨頁面捲動。在個案名單的「篩選個案」欄位尋找個案；個案分頁支援方向鍵、Home 與 End 切換。

個案摘要顯示紀錄總數、最近紀錄日期，以及最近一筆紀錄中的下次復健日期。「復健紀錄」分頁顯示症狀圖表與由新到舊排列的紀錄歷程；寬螢幕時圖表在歷程旁，窄螢幕時在歷程上方。依紀錄類型與日期篩選只改變列出的紀錄，不影響個案摘要。「進度追蹤」顯示症狀變化、評估結果、COPM 比較與訓練紀錄；「項目設定」管理該個案的評估與復健模板。

首次開啟時跟隨系統外觀，從「檢視」手動切換後，設定會記在目前的瀏覽器。淺色模式採白色工作面、淺灰底、青綠重點與細分隔線；深色模式沿用相同的資訊層級。Noto Sans TC 使用電腦已安裝的字體，或選用的本機檔案 `EzEMR-assets/NotoSansTC-VF.ttf`，無法使用時由系統字體備援。

## 自訂評估與復健項目

選取個案後，開啟「項目設定」：

1. 按「新增評估項目」或「新增復健項目」，選擇內建模板或空白模板。
2. 填寫項目名稱。評估可設定領域、填寫說明與評估時機；復健可設定活動清單，每行一項。
3. 新增結果欄位，選擇文字、數值、長文字或選單。數值可設定單位、最小值、最大值與間隔；選單選項每行一項。
4. 按「儲存項目」，之後即可在 SOAP 表單勾選並填寫。也可直接從正在填寫的 SOAP 表單新增項目，原有草稿會保留。

### 初次評估項目

「項目設定」最上方的「初次評估項目」以勾選方塊列出個案所有啟用中的評估項目。勾選初次評估（基準評估）要施測的項目，每次變更都會立即儲存。沒有調整過的項目預設列入，既有個案的使用方式不變。

病歷中的評估項目改用勾選方塊，做法參考 NTUHLowvision 的門診評估表單：

- 「基準評估」先列出初次評估項目，其餘列在「其他項目」。
- 「療程後評估」與「追蹤評估」將初次評估項目中依評估時機應再評估的項目列為「本次應評估」，其餘列在「其他項目」。
- 一般復健紀錄列出所有可用的評估項目，不另分應評估群組。COPM 只在基準與療程後評估顯示。

勾選項目後展開結果欄位；取消勾選會收合，離開這筆紀錄前已輸入的內容仍保留。只有勾選的項目會存入紀錄，沒施測的項目不會出現在病歷、PDF、Excel 或進度追蹤。舊紀錄中未勾選但已存有的結果會保留。

### 復健項目與活動分數

復健項目採相同方式：勾選本次進行的項目後展開。在項目內勾選做過的活動，每個勾選的活動各有一個分數欄，例如 `85%`、`12 次` 或 `40 秒`。其後為共用的程式／設備、時間、級別／設定、個案自評難度（0 至 10）與觀察，再接自訂結果欄位。沒有活動清單的項目改為單一「表現」欄。舊紀錄使用過的共用表現欄會以「整體表現」保留。

活動分數會寫入病歷、PDF 與 TXT（例如「選擇性注意力：92%」），在 Excel 的 Training results 工作表各占一列，在「進度追蹤」中每個活動各占一欄；✓ 表示有做但未填分數。自評難度與整體耐受度改用 0 至 10 的數字欄，空白代表未評分，超出範圍時無法儲存。COPM 保留專用表格、評估時機及基準比較。

### 電腦化視覺測驗（OcuTrain 與 UFOV）

內建的電腦化測驗依照 OcuTrain 的模組與周邊視野訓練程式的子測驗設定。每個模組或子測驗是獨立的項目，平滑追視與凝視不會寫在同一項：

| 項目 | 主要分數 | 其他結果 | 測驗設定 |
| --- | --- | --- | --- |
| 平滑追視（OcuTrain PURSUIT） | 注視正確率（%） | 完成目標數、命中時間、有效注視時間、測驗時間、各方向複視出現位置 | 測驗模式、刺激類型與大小、移動速度、目標範圍、方向、命中距離閾值、觀看距離、眼動儀 |
| 凝視（OcuTrain FIXATION） | 注視正確率（%） | 同平滑追視 | 同平滑追視，另加邊緣停留時間 |
| 跳視（OcuTrain SACCADE） | 注視正確率（%） | 平均首次凝視時間（TFF）、TFF 目標數及上述結果 | 測驗模式、刺激、目標停留時間、範圍、方向、閾值、距離、眼動儀 |
| 前庭眼反射（OcuTrain VOR） | 注視正確率（%） | 命中時間、有效注視時間、測驗時間、複視 | VOR 倍率、VOR 方向、刺激大小、閾值、距離、眼動儀 |
| UFOV 子測驗 1 至 3（處理速度、分散注意力、選擇性注意力） | 80% 正確門檻（ms） | 整體正確率、平均反應時間、正式題數與答對題數、最快正確呈現時間；子測驗 2、3 另有中央與周邊正確率及各方向正確率 | 停止條件、對比度、車輛大小、觀看距離、螢幕更新率；子測驗 2、3 另有周邊偏心視角與啟用方向 |

主要分數排在第一欄。測驗設定收合在結果下方的「測驗設定」區，標題會顯示已填幾項。欄位代碼沿用兩個程式匯出檔的鍵名，匯入的數值會填入相同的欄位。病歷、PDF 與進度追蹤以一行摘要顯示設定。

復健紀錄也可以記錄測驗。勾選「電腦眼球運動訓練」或「周邊覺察」後，「測驗紀錄」每次測驗列一張卡片。選擇模組或子測驗後按「新增測驗紀錄」即可手動填寫。每張卡片有自己的結果與設定，同一次復健做的追視與凝視會分開記錄。測驗紀錄會寫入病歷與 PDF，在 Excel 的 Training results 工作表各占一列，並在進度追蹤中以獨立標題顯示。

既有個案保留原本存好的項目模板。舊的項目，例如合併的凝視、追視項目，仍可使用，已存的結果不變。可從「項目設定」加入新項目，或由匯入測驗分數時自動加入。

每個項目可編輯、複製、停用或再次啟用。已儲存的病歷保留當時的項目名稱與欄位定義，後續模板改名、移除欄位或停用，不會改寫歷史結果。舊版尚未保存定義的病歷，會在第一次修改設定時，由個案資料保留原模板。

新增個案時，「評估與復健項目模板」可複用其他個案的項目定義，只複製設定，不複製病歷或評分；兩位個案後續的設定各自保存。

## 💾 儲存結構與檔案格式

HTML 沒有寫死病歷資料夾的絕對路徑，選擇儲存位置也不會修改 HTML 檔案。病歷會存在 HTML 旁或你選擇的其他本機資料夾。

使用預設 `Data` 位置時的資料夾範例：

```text
EzEMR/
  EzEMR.html
  Data/
    clients.csv
    MRN-001/
      2026-10-30_S01_基準評估.csv
      2026-10-30_S01_基準評估.pdf
      2026-10-30_S01_基準評估.txt
      2026-10-31_S02_復健.csv
      2026-10-31_S02_復健.pdf
      2026-10-31_S02_復健.txt
```

個案資料夾使用病歷號命名，未填病歷號時使用姓名。病歷檔名由日期、次數與紀錄類型名稱組成；切換介面語言不會更改既有檔名。

| 檔案 | 內容與行為 |
| --- | --- |
| `clients.csv` | 每位個案一列，包含識別碼、資料夾名稱、姓名、病歷號、出生與發病日期、診斷、轉介原因、手術史、評估與復健模板、建立日期及額外資料。手術史與模板等巢狀資料以 JSON 格式放在單一 CSV 儲存格內。 |
| 每次病歷的 `.csv` | 每個欄位一列，包含 `schema_version`、`section`、`field`、`type`、`value` 五欄，保存數值、空值、勾選狀態、症狀、評估、COPM 與訓練資料，可重新匯入。例如 `section` 為 `session`、`field` 為 `/subjective` 的資料是主觀描述。 |
| 每次病歷的 `.pdf` | A4 圖像版文件，自動換行與分頁，可閱讀及列印。文字無法直接選取或搜尋，需要搜尋或分析資料時請使用 CSV。 |
| 每次病歷的 `.txt` | 同一份病歷的純文字版，使用儲存時的介面語言。每次儲存都會重寫，程式不會讀回；重新匯入請使用 CSV。 |

CSV 使用 UTF-8 BOM，支援中文與 Excel 開啟。新增、編輯、項目設定或刪除個案時會更新 `clients.csv`，不需要另外的 JSON 資料庫。

每次新增病歷產生一組 CSV、PDF 與 TXT；編輯同一筆紀錄會更新原有檔案。檔名在首次儲存時決定，之後修改日期或次數仍保留原檔名，實際資料以檔案內容為準。不同紀錄的檔名相同時，會自動加上編號避免覆寫。

### 瀏覽器如何記住資料夾

主要病歷資料夾與選用的副本資料夾，會以檔案系統控制代碼（handle）記在瀏覽器的 IndexedDB。這些資料夾參照不會寫入 `EzEMR.html`，也不包含在 JSON 備份中。啟動時，若記住的主要資料夾仍有權限，便會自動連接；否則第一個畫面會提供重新連接。可從「檔案 → 開啟病歷資料夾」切換資料夾。

`Data` 只是固定的預設子資料夾名稱，並非固定路徑。程式會在首次儲存時選取的上層資料夾內建立或開啟它。若要放在 HTML 旁，請選擇 `EzEMR.html` 所在的資料夾。重新開啟既有病歷時，請直接選取 `Data`，或其他包含 `clients.csv` 的病歷資料夾。

換瀏覽器、瀏覽器使用者設定檔或電腦後，需要重新選取資料夾並授權。清除瀏覽器資料會移除記住的資料夾存取資訊與存在瀏覽器中的紀錄，但不會刪除已儲存在本機病歷資料夾的檔案。

### 更換儲存位置

開啟「檔案 → 儲存位置」。可以直接選擇 HTML 所在的資料夾，讓 `clients.csv` 與 HTML 放在同一層，也可以使用 `Data` 或其他本機資料夾。已有病歷時，選擇包含 `clients.csv` 的資料夾；開始新的資料集時，選擇空資料夾。切換後會讀取新位置，原位置的檔案仍保留，不會自動搬移或複製病歷。

### 重新讀取本機資料

本程式直接讀寫你選取的本機資料夾。在程式外修改檔案後，可選「檔案 → 重新讀取資料夾」載入變更。

### 更新程式或搬移病歷

更新程式前，先儲存草稿並保留完整病歷資料夾；使用瀏覽器儲存時，請匯出完整 JSON 備份。更換 `EzEMR.html` 後，再視需要重新連接既有資料夾或還原備份。移動 HTML 不會搬移本機病歷資料夾。

需要換資料夾或電腦時，先儲存正在編輯的草稿，再選擇其中一種方式：

- 複製完整病歷資料夾，包含 `clients.csv` 與所有個案子資料夾；換電腦時也要複製 `EzEMR.html`。開啟 HTML 後，從「檔案 → 開啟病歷資料夾」選擇複製後包含 `clients.csv` 的資料夾。此方式保留既有檔案與檔名。
- 從「備份全部資料（JSON）」匯出備份，將備份與需要的 `EzEMR.html` 複製到新位置。開啟 HTML，選取空的目的病歷資料夾，再以「匯入」還原 JSON。還原會將個案資料寫入選定位置，並建立各次病歷的 CSV、PDF 與 TXT。

如果使用第二個副本資料夾，請在目的地的瀏覽器重新設定。

## 匯入、匯出與備份

- 從工具列「匯入」或「檔案 → 匯入 CSV／評估復能 Excel／備份／測驗分數」，可一次選擇多份本程式產生的 CSV、匯入個案總表、還原單一完整 JSON 備份、讀取支援格式的 `.xlsb`／`.xlsx` 來源資料表，或匯入測驗分數檔。Excel、CSV、JSON 與測驗分數檔請分開匯入。
- 從「匯出 → 匯出個案總表 CSV」下載 `clients.csv`；「匯出個案 Excel／匯出全部個案 Excel」產生活頁簿；「備份全部資料（JSON）」保存完整資料備份。
- 自訂評估、復健與結果欄位會出現在進度追蹤、CSV、PDF、Excel 與完整備份。即使篩選到療程後紀錄，COPM 仍會與完整歷程中對應的基準紀錄比較。
- 資料夾模式可從「檔案 → 設定副本資料夾」選擇第二個本機資料夾。連接時複製既有資料，之後的寫入、重新命名與刪除也會套用至副本；需要保留不受後續刪除影響的版本時，另行保存 JSON 備份。

### 測驗分數檔

先選取個案，再按「匯入」並選擇一或多個分數檔。程式依檔案內容辨識格式，不看檔名：

- OcuTrain 的 JSON 匯出檔（包含一個檔案內有多次測驗的情況），以及開頭為 `# Key: Value` 的 OcuTrain CSV 匯出檔。支援追視、凝視、跳視與 VOR。
- 周邊視野（UFOV）訓練程式的統計成績 CSV，欄位為 `參數項目`、`參數代碼`、`設定數值`、`單位`、`詳細說明`。

預覽畫面每次測驗列一張卡片，顯示日期時間、項目、測驗模式、主要分數、檔名，以及「匯入為」選單：「評估」、「復健訓練」或「不匯入」。預設規則：

- OcuTrain 的評估（Evaluation）模式匯入為評估；可預期（Predictable）與隨機（Random）模式匯入為復健訓練。
- UFOV 測驗在同一天已有評估紀錄時匯入為評估，否則匯入為復健訓練。
- 未完成的測驗、UFOV 的練習或說明模式，以及已匯入過的測驗，預設為「不匯入」。匯入前可逐筆修改。

匯入為評估時，會填入當天紀錄中該項目的欄位。匯入為復健訓練時，會在對應的復健項目下新增一筆測驗紀錄，主要分數成為該活動的分數。當天沒有紀錄時，匯入會新增評估或復健紀錄。不會覆蓋已有的結果：數值與已存結果不同的測驗會略過並列在報告中。同一次測驗同時匯出 JSON 與 CSV 時只列出一筆。

檔案中的受試者代號若與其他個案的病歷號相同，匯入會停止。UFOV 原始分數 CSV 只有逐題資料，UFOV 的 JSON 匯出檔沒有記錄測驗模式，兩者都只列為說明、不匯入，請改匯入同一次的統計成績 CSV。與測驗一起存的複視問卷會填入該次的複視欄位；只有問卷的檔案不會匯入。每筆匯入的測驗都會在紀錄的來源資訊中保留檔名、受試者代號、測驗日期時間與匯入鍵值。

### 來源資料表與舊版 SOAP 資料夾

Excel 匯入需要包含「評估及復能收案名單」、「評估紀錄」與「復能紀錄」三張工作表，並沿用來源資料表的欄位結構，不支援任意格式的 Excel。匯入後保留工作表名稱、列號與原始欄位值；個案與病歷畫面會顯示可用的來源資訊及醫療史。

從「檔案 → 匯入舊版 SOAP 資料夾」選擇包含個案子資料夾的上層目錄；每組 JSON 病歷須與該個案的 `client.json` 放在同一資料夾。匯入會略過 `_archive`，同一筆病歷識別碼保留 `updated` 較新的版本，合併符合條件的個案與紀錄，並回報資料衝突。整合來源資料前，請先備份目的位置。

### 舊版資料相容性

舊版 `client.json` 與 JSON 病歷仍可讀取。沒有總表時，儲存個案會建立 `clients.csv`；已有總表時以總表為準，格式錯誤會停止讀取，避免覆寫。

編輯舊病歷後會產生 CSV、PDF 與 TXT，原有 JSON 保留；同一筆紀錄同時存在 CSV、JSON 時，以 CSV 為準。

## 離線使用與瀏覽器儲存

HTML 已內嵌 Excel 元件，病歷編輯、CSV／PDF 儲存、支援格式的 Excel 匯入及 Excel 匯出均可離線使用。字體使用本機或系統檔案。程式仍保留 jsDelivr 備援，僅在 `window.XLSX` 無法使用時嘗試下載 Excel 元件。

瀏覽器不支援資料夾存取時，改用瀏覽器儲存。每次儲存病歷會下載 ZIP，內含以病歷號命名的資料夾與該次 CSV、PDF；未填病歷號時以姓名命名。請自行解壓縮並合併到病歷資料夾，此模式不會直接更新磁碟上的固定資料夾。

瀏覽器暫存不能取代下載檔或備份。清除瀏覽器資料會移除存在其中的紀錄。

## 專案檔案與驗證

```text
.gitignore             排除測試暫存檔與本機 Data 資料夾
.gitattributes         保持 Git hook 的跨平台換行格式
.githooks/pre-push     每次推送前執行完整 CI
.github/workflows/     推送與 PR 時自動執行完整 CI
AGENTS.md              開發與推送規則
EzEMR.html             主程式，內嵌 Excel 元件
LICENSE                MIT 授權
README.md              英文說明
README.zh-TW.md        繁體中文說明
tests/                 瀏覽器測試與 PDF／ZIP 檢查
  VERIFICATION.md      測試環境、涵蓋範圍與限制
  run-ci.cjs           Git hook 與 GitHub Actions 共用的完整測試入口
  ci-runner.cjs        驗證失敗處理與停止後續步驟
  rehab-note.cjs       病歷流程、儲存與匯出測試
  storage.cjs          個案總表與資料夾測試
  toolbar.cjs          選單、工具列與快捷鍵測試
  templates.cjs        自訂項目與外觀測試
  assessment-picks.cjs 初次評估項目、勾選展開與各活動分數的雙語測試
  language.cjs         語言切換與資料保留測試
  score-imports.cjs    OcuTrain 與 UFOV 分數匯入、測驗設定與測驗紀錄的雙語測試
  imports.cjs          空白啟動、離線 Excel 與舊版 SOAP 匯入的雙語測試
  workspace.cjs        直接開啟檔案、個案摘要、篩選、鍵盤分頁與版面檢查
  check_i18n.cjs       原始碼翻譯與英文文件檢查
  check_exports.py     獨立 PDF 與 ZIP 驗證
```

使用主程式不需要安裝套件。開發驗證需要 Node.js、Acorn、Playwright 與 Chromium，以及 Python 的 `pypdf`、`PyMuPDF`。環境設定與執行指令見 [tests/VERIFICATION.md](tests/VERIFICATION.md)。

安裝測試依賴後，每份 checkout 執行一次，啟用 Git hook：

```sh
git config --local core.hooksPath .githooks
```

之後每次 `git push` 都會執行 `node tests/run-ci.cjs`，GitHub Actions 也會在推送與 PR 時執行同一條指令，檢查雙語、病歷流程、儲存、選單、模板、語言切換、匯入、版面、PDF／ZIP 匯出，以及測試入口的失敗處理。任何一項失敗都會停止後續步驟並阻止本機推送。新增到 `tests/` 的 `.cjs`、`.py` 測試腳本會自動納入；固定版本的 Excel 測試元件首次執行時下載，之後從 `.tmp/` 重複使用。

每個介面功能都必須具備繁體中文與英文。翻譯檢查會攔截漏翻文字、新增的單一語言標籤、缺少另一種語言的內建項目，以及英文 README 的中文字。新增功能的畫面與狀態也必須納入雙語瀏覽器測試，規則見 [AGENTS.md](AGENTS.md)。

`.tmp/` 已由 Git 忽略，用來存放測試結果、畫面、匯出測試檔與下載的 Excel 測試元件，使用主程式不需要這些檔案。

若 `EzEMR.html` 內嵌了個案資料，測試會失敗。測試在獨立瀏覽器環境建立合成個案；`imports.cjs` 另直接從磁碟開啟公開版 HTML，再使用獨立資料夾測試合成 Excel 與舊版 SOAP 匯入。雙語檢查包含匯入報告、錯誤、來源標籤、日期、重複紀錄與封存排除。原生作業系統資料夾對話框與臨床適用性不在自動化驗證範圍內。

翻譯檢查會排除不可執行的 JSON 資料，並以固定 SHA-256 雜湊驗證內嵌 Excel 元件。應用程式腳本、匯入訊息、無障礙名稱及內建評估項目的雙語標籤仍須通過翻譯檢查。來源資料表的工作表名稱與欄位名稱屬於資料識別值，兩種語言下都保持不變。反例測試確認漏翻介面或修改第三方元件仍會失敗。
